# 全司房源价格管理核对工作台

固定入口：https://heifengzhaimogu-wq.github.io/-/price-desk/

六店示例：https://heifengzhaimogu-wq.github.io/-/price-desk/?demo=1

## 进入方式

按用户最新要求，使用工号后四位或完整工号、店面关键词、职位关键词匹配已登记员工档案，不需要密码、个人邮箱或激活链接。首位推进负责人可填 0321 / 全司 / 全司推进负责人。两个或更多推进负责人使用各自已登记工号。

服务端按三项与启用档案匹配，页面选择职位不能直接授予权限。多位员工匹配时要求完整工号及更精确店名。匹配成功后服务端签发正常 Supabase 用户会话，数据表继续执行基于员工档案的 RLS。此方式是轻量访问校验，三项信息不是秘密或强身份凭证，知情者可能冒用；不能将其描述为强身份认证。

不发送邮件。系统内部仍使用生成的 Auth 标识，不收集员工个人邮箱。服务端管理密钥只存在 Edge Functions 环境中，前端只含公开 publishable key。增加了匹配尝试限频。旧密码激活接口已停用。

## 权限与身份

| 身份 | 进度范围 | 价格 |
| --- | --- | --- |
| 全司推进负责人 | 全司、各店、各组、个人 | 不可见 |
| 门店 BP | 本店、各组、个人 | 不可见 |
| 店总 | 本店、各组、个人 | 不可见 |
| 店经理 | 本组及组员 | 本组可见 |
| 顾问 | 本人房源，可核对与处理 | 本人可见 |

侧栏显示当前员工姓名、工号、职位、店面、小组、店面负责人。负责人可在数据管理的成员与权限中登记门店负责人；未登记时显示未登记，不虚构姓名。角色、店组和人员范围由档案与数据库策略决定，不受客户端选择影响。

## 三个模块

日常推动以整改完成率、已完成/需整改数量为主。可展开门店、小组、个人层级，并查看个人具体未完成房源。保留店、组、个人、批次、状态筛选，新增数据所属日期的起止筛选和本周、本月、全部记录预设。数据记录展示业务日期、来源文件、上传时间和截止日。默认当月所有批次；导入历史数据后自动定位其所属月份。

周月复盘支持周度、月度、自定义期间，按业务数据所属日期统计，截至当前处理状态。旧批次未记录业务日期时使用上传日期回退，不将当前状态假装成历史期末快照。支持门店、小组、人员对比、任意两个对象比较、目标差距、标杆及重点跟进文案，并可复制和导出。所有视图与导出使用相同的权限和期间范围。

标杆观察默认完成率不低于90%，低完成率跟进默认低于60%，最小样本5套，均可在分析口径中调整。样本不足、没有整改分母、完成率相同等情况明确披露；不编造高低差异，不据完成率推断能力或根因。业务目标独立于分析阈值。

数据管理提供错误清单或全量清单导入、责任人分配预览、目标设置、成员权限及批次历史。错误清单全部计入整改分母；全量清单按是否需调整、错误类型来源标记识别，未配置独立的外部自动比价规则。已知错误不能直接选择无需调整。

导入字段：编号、店面、小组、顾问姓名、顾问工号、楼盘、房间号、报价、底价；可选是否需调整、错误类型。支持房源编号、门店、组别、工号、楼盘名称、房号、系统报价等常见别名。如果工号能唯一匹配已登记顾问，缺失姓名、店面、小组可自动补齐；无法确定归属时拒绝整批，不猜测人员。完整工号及房号请使用文本格式保留前导零。

顾问提交调价后进入待完成状态，实际在业务系统改好后再勾选确认完成。本工具没有自动写入外部房源系统。“完成”来自顾问确认。核对前价格快照保留。

## 数据口径

核对完成率 = 已核对任务数 / 全部任务数。整改完成率 = 已完成整改 / 已识别需整改任务。来源已标记需整改的房源即使未核对，也计入分母。没有需整改任务时显示横线，未全部完成时不因四舍五入提前显示100%。每个批次为独立核对任务，同一房源跨批次按任务套次累计。

周月目标由推进负责人配置，未配置显示未设置。全司套数目标不自动重复用于每个店或小组。正式系统不预置演示目标或虚构房源；六店示例仅在 demo 参数下存在。

## 开发与恢复

当前前端入口为 source/src/workbench.js；上代 src/app.js 等保留但不参与构建。npm ci、npm test、npm run build；dist 四个前端文件发布回原 price-desk 目录，主链接不变。静态资源版本需随发布更新。

V2 基础脚本依次为 database-workflow.sql、database-staff-upgrade.sql、database-workflow-baseline.sql、database-staff-collision.sql；之后应用 database-modules.sql、database-experience.sql、database-dataset-date.sql。当前增量升级不删除已有业务数据。公开的 desk_staff_invite / desk_invite 及私有 invite 执行权限已撤销，旧激活接口返回410。

Edge Functions：desk-staff-login 负责匹配员工档案并在服务端生成、消费一次性 Auth 令牌以签发会话，不将内部令牌交给前端；desk-activate-account 为弃用提示。正式身份弱校验的风险按上文说明，RLS 不等于对身份真实性的强验证。
